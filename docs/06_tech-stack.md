# 技術選定資料

oshi-tomo で使う技術と、選んだ理由です。Week 21 で確定しました。

## 選び方の方針

1. **教材の推奨技術スタックを基本にする**（Week 22〜24 の教材に沿って作れるようにするため）
2. **ブログアプリ（Week 1〜17）で使った技術・構成を使い回す**（初めて使う技術を減らし、3週間で MVP を作りきるため）
3. **MVP に必要ない技術は使わない**（ブログアプリで使えた技術でも、必要になってから足す）

## 使用技術一覧

### バックエンド

| 技術 | バージョン | 選んだ理由 |
|------|-----------|-----------|
| PHP | 8.2 | 教材の推奨。ブログアプリと同じ |
| Laravel | 12.x | 教材の推奨。ブログアプリと同じ |
| Laravel Breeze（Blade） | 2.x | 会員登録・ログイン・ログアウトを用意してくれる。会員登録に生年月日を足すだけで F-01 を作れる |
| MySQL | **8.4** | 本番で使う RDS（ブログアプリと共用）が 8.4.11 のため、開発環境もそろえる。※教材の推奨は 8.0 |

### フロントエンド

| 技術 | 選んだ理由 |
|------|-----------|
| Blade | 教材の推奨。総合プロジェクトは Blade の Web アプリとして作る |
| Tailwind CSS | 教材の推奨。Breeze に最初から入っている。スマートフォン向けの画面を作りやすい |
| Alpine.js | 教材の推奨。Breeze に最初から入っている。メニューの開閉など、小さな動きに使う |
| fetch（JavaScript） | 「行きたい！」（F-07、Ajax）で、ページを再読み込みせずに POST して JSON を受け取るため |

### インフラ

| 技術 | 選んだ理由 |
|------|-----------|
| Docker（nginx・app・mysql コンテナ） | 開発環境。ブログアプリの構成を使い回す。mysql コンテナは `mysql:8.4` にする |
| AWS（EC2 + Docker + RDS） | 本番環境。下の「デプロイ先」を参照 |
| 画像の保存先：ローカル（storage） | 教材の必須はローカル保存。S3 は発展 |
| ドメイン：`oshi-tomo.rabblog.com` | Week 13 で取得した rabblog.com のサブドメイン。新しくドメインを買わなくてよい |

### 開発ツール

| 技術 | 選んだ理由 |
|------|-----------|
| Git / GitHub（Issues・Projects） | タスク管理。Issue を閉じながら実装を進める |
| GitHub Actions | CI/CD。テスト → イメージのビルド → EC2 へデプロイ。ブログアプリで構築済み |
| PHPUnit | テスト。受け入れ基準（Policy の 403 など）を Feature テストで確かめる |
| PHPStan・PHP CS Fixer | コードの品質チェック。ブログアプリと同じ |
| Laravel Debugbar | 開発中に SQL の回数（N+1 問題）を確かめる |
| Figma | 画面設計 |
| Claude Code | 実装の補助 |

## デプロイ先

**A：AWS を使い続ける** を選んだ。

| 比べたこと | A：AWS | B：Render など |
|-----------|--------|---------------|
| 環境の準備 | EC2・RDS・ドメイン・SSL 証明書・CI/CD が Week 13〜16 で動いている | 新しく作る必要がある |
| データベース | RDS のため、データが消えない | 無料の DB は30日で使えなくなることがある |
| アップロードした画像 | EC2 の storage に残る | 再デプロイで消える |
| マイグレーション | EC2 にログインして実行できる | シェルが使えず、起動時の CMD で実行する |
| 費用 | 無料プランのクレジットの範囲（月 3〜5 ドル程度、2027-04-18 まで） | 無料 |

- 画像アップロード（F-06）は必須の機能で、**画像が消えない**ことが大事なため A にした
- 構成図は [05_infrastructure/infrastructure.md](05_infrastructure/infrastructure.md)
- 本番へのデプロイは、最初の提出（12/9）の後に行う

## 今回は使わない技術

ブログアプリで使ったが、MVP には必要ないため使わない。必要になったら足す。

| 技術 | 使わない理由 | 使うとしたら |
|------|-------------|-------------|
| Redis（キャッシュ） | 最初は利用者もデータも少なく、一覧が遅くならない | 利用者が増えて、募集一覧の表示が遅くなったら |
| S3・CloudFront（画像の保存・配信） | 教材の必須はローカル保存。1台の EC2 で足りる | 発展として、画像が増えたら |
| API とフロントエンドの分離（React など） | 教材で発展（任意）。Blade のほうが3週間で作りきれる | 今回は使わない |
| リアルタイム通信（WebSocket） | チャットは Won't のため | 今回は使わない |
