# 練習課題2：ユーザーストーリー作成

練習課題1の架空のクライアント「○○酒造」の EC サイトについて、主要機能をユーザーストーリーで記述したものです。

## 登場人物

| 登場人物 | どんな人？ |
|---|---|
| お客さん（購入者） | 直売所で飲んで気に入った観光客など。家に帰ってからもリピートしたい |
| 店の担当者 | サイトを更新する従業員（パソコンがある程度できる人） |

## お客さんの買い物の流れ

自分がネットで買い物をするときの流れをもとに考えた。

```
商品を探す（欲しいものがある → 検索／見ているだけ → おすすめ・ジャンル）
  → 商品の詳細を見る（説明・写真・お届け日数・送料）
  → 信頼できるお店か確認する
  → 個数を選んでカートに入れる
  → お届け先・支払い方法を入力して注文する（年齢確認）
  → 注文確認のメールが届く
  → 2回目は、購入履歴やクーポンを使って楽に・お得に買う
```

## ユーザーストーリー

### お客さん（購入者）

| No | 誰が | 何をしたい | なぜなら |
|---|---|---|---|
| US-01 | お客さん | 商品名で検索したい | 欲しいお酒がすぐ見つかるから |
| US-02 | お客さん | おすすめやジャンル（純米酒・吟醸酒など）から商品を見たい | 欲しいものが決まっていなくても、好みのお酒を見つけたいから |
| US-03 | お客さん | 商品の説明や写真を見たい | どんな味か分かってから買いたいから |
| US-04 | お客さん | お届け日数と送料を知りたい | いつ届いて、合計いくらになるか分かってから買いたいから |
| US-05 | お客さん | 蔵の紹介やお店の情報を見たい | 初めて買うお店が信頼できるか確かめたいから |
| US-06 | お客さん | 個数を選んでカートに入れたい | ちがうお酒をまとめて買いたいから |
| US-07 | お客さん | お届け先と支払い方法を入力して注文したい | 家にお酒を届けてもらうため |
| US-08 | お客さん | 注文確認のメールを受け取りたい | ちゃんと注文できたか安心したいから |
| US-09 | お客さん | 会員登録して、購入履歴を見たい | 2回目に住所を入れ直さず、前と同じお酒をすぐ買いたいから |
| US-10 | お客さん | 2回目の購入でクーポンを使いたい | お得にリピートしたいから |

### 店の担当者

| No | 誰が | 何をしたい | なぜなら |
|---|---|---|---|
| US-11 | 店の担当者 | 商品を登録・編集したい | 新しいお酒をサイトで売るため |
| US-12 | 店の担当者 | おすすめ商品を選んで表示したい | 季節のお酒や自信作を知ってもらうため |
| US-13 | 店の担当者 | 在庫数を管理したい | 売り切れたお酒が注文されないようにするため |
| US-14 | 店の担当者 | 注文の一覧を見て、発送済みにしたい | 注文を見落とさず、お客さんに発送を知らせるため |
| US-15 | 店の担当者 | どの商品が売れているか見たい | 売れ筋を知って、目標（1年後に月50本）に近づいているか確かめるため |

### 法律による要件（ヒアリングの制約条件から）

| No | 誰が | 何をしたい | なぜなら |
|---|---|---|---|
| US-16 | 店の担当者 | 注文時にお客さんの年齢を確認したい | 20歳未満にはお酒を売れないため |

## 考えたこと

- 同じお客さんでも、「欲しいものが決まっている人」と「見ているだけの人」では使う機能がちがうので、検索（US-01）とおすすめ・ジャンル（US-02）を分けた
- 初めて聞く小さな酒蔵からネットで買うのは不安なので、信頼できるお店か確かめられるストーリー（US-05）を入れた
- ヒアリングで分かった「観光客がリピートしたくても買えない」という課題から、2回目を楽にするストーリー（US-09・US-10）を入れた
- EC サイトは、売る側がいないと動かないので、店の担当者のストーリー（US-11〜US-15）も入れた
- US-16 は、お客さんがしたいことではなく、お店が法律で守らないといけないこと。お客さんの声だけでは見落としやすいので、ヒアリングで「法律・規制」を聞くことが大事
