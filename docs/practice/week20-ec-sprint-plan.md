# 練習課題1：スプリント計画

Week 18 の架空のクライアント「○○酒造」の EC サイトを、3つのスプリントに分けて計画したものです。

- ユーザーストーリーは [week18-user-stories.md](week18-user-stories.md) の US-01〜US-16
- ヒアリングの結果は [week18-hearing-sheet.md](week18-hearing-sheet.md)、要件は [week18-requirements-clarification.md](week18-requirements-clarification.md)

## 1. 前提

| 項目 | 内容 |
|------|------|
| 開発者 | 1人 |
| スプリントの長さ | 1週間 × 3スプリント |
| 1スプリントで使える時間 | 23時間 |
| 見積もりの単位 | ストーリーポイント（1ポイント ＝ 1時間の目安） |

### ヒアリングで分かった制約

| 制約 | 内容 | 計画への影響 |
|------|------|-------------|
| 予算 | 30万円くらい | 時給 4,000円で約 75時間。US-01〜US-16 を全部は作れないため、**売り始めるのに必要なもの** に絞る。要件定義・設計も含めると予算を少し超えるため、予算に合わせる案は見積書（[week20-ec-estimate.md](week20-ec-estimate.md)）で出す |
| 納期 | お歳暮の時期までに販売を始めたい | 3スプリント（3週間）で、注文を受けて発送できるところまで作る |
| 法律 | 20歳未満には売れない | 年齢確認（US-16）は、注文と同じスプリントで必ず作る |
| 体制 | サイトを動かすのは、パソコンがある程度できる従業員 | 商品の登録や注文の確認は、管理画面からできるようにする |

## 2. ユーザーストーリーの優先順位

### 並べ方の考え方

1. **売り始めるのに必要なものを先に作る**：商品を見る → カートに入れる → 注文する → 店が発送する、の流れがつながれば、お歳暮の時期に売り始められる
2. **法律で必要なものは、関係する機能と一緒に作る**：年齢確認（US-16）がないと、注文を受け付けられない
3. **リピートのための機能は次の段階にする**：会員登録・購入履歴・クーポンは、社長の目標（1年後に月50本）には大事だが、まず売り始めることを優先する

### 優先順位

| 順位 | US | 内容 | スプリント |
|------|----|------|-----------|
| 1 | US-11 | 店の担当者が、商品を登録・編集する | 1 |
| 2 | US-03 | お客さんが、商品の説明や写真を見る | 1 |
| 3 | US-02 | お客さんが、ジャンル（純米酒・吟醸酒など）から商品を見る | 1 |
| 4 | US-06 | お客さんが、個数を選んでカートに入れる | 2 |
| 5 | US-07 | お客さんが、お届け先と支払い方法を入力して注文する | 2 |
| 6 | US-16 | 店の担当者が、注文時にお客さんの年齢を確認する | 2 |
| 7 | US-04 | お客さんが、お届け日数と送料を知る | 2 |
| 8 | US-08 | お客さんが、注文確認のメールを受け取る | 2 |
| 9 | US-14 | 店の担当者が、注文の一覧を見て発送済みにする | 3 |
| 10 | US-13 | 店の担当者が、在庫数を管理する | 3 |
| 11 | US-05 | お客さんが、蔵の紹介やお店の情報を見る | 3 |
| 12 | US-01 | お客さんが、商品名で検索する | 3 |
| 13 | US-09 | お客さんが、会員登録して購入履歴を見る | 次の段階 |
| 14 | US-10 | お客さんが、2回目の購入でクーポンを使う | 次の段階 |
| 15 | US-12 | 店の担当者が、おすすめ商品を選んで表示する | 次の段階 |
| 16 | US-15 | 店の担当者が、どの商品が売れているか見る | 次の段階 |

## 3. スプリントの全体像

| スプリント | 使える時間 | 作業 | 余裕 | スプリントゴール |
|-----------|-----------|------|------|-----------------|
| 1（1週目） | 23h | 22pt | 1h | 店の担当者が商品を登録でき、お客さんが商品を見られる |
| 2（2週目） | 23h | 20pt | 3h | お客さんがカートに入れて、年齢を確認したうえで注文できる |
| 3（3週目） | 23h | 20pt | 3h | 店の担当者が注文を処理でき、本番環境で売り始められる |
| **合計** | **69h** | **62pt** | **7h** | |

## 4. 各スプリントの計画

### スプリント1（1週目）：商品を見られる

**ゴール**：店の担当者が商品を登録でき、お客さんが商品の一覧・詳細を見られる

| 作業 | US | ポイント |
|------|----|---------|
| 環境構築（Laravel・Docker） | - | 3 |
| マイグレーション・モデル（商品・ジャンル） | - | 3 |
| 共通レイアウト（スマートフォンでも横スクロールなしで見られる） | - | 3 |
| 管理画面のログイン（店の担当者だけが入れる） | - | 2 |
| 商品の登録・編集（名前・説明・価格・写真・ジャンル） | US-11 | 5 |
| 商品の詳細ページ | US-03 | 3 |
| 商品の一覧・ジャンルで絞り込み | US-02 | 3 |
| **合計** | | **22** |

### スプリント2（2週目）：注文できる

**ゴール**：お客さんがカートに入れて、年齢を確認したうえで、会員登録なしで注文できる

| 作業 | US | ポイント |
|------|----|---------|
| カート（個数の選択・変更・削除） | US-06 | 5 |
| 注文（お届け先・支払い方法の入力、確認、完了） | US-07 | 5 |
| 年齢確認（注文時に生年月日を入力し、20歳未満は注文できない） | US-16 | 2 |
| 送料・お届け日数の表示 | US-04 | 2 |
| 注文確認メール（お客さんと店の担当者に送る） | US-08 | 3 |
| テスト（カート・注文・年齢確認） | - | 3 |
| **合計** | | **20** |

- 支払い方法は、今の電話注文と同じ **銀行振込** と **代金引換** にする。クレジットカード決済（外部サービスとの連携）は次の段階で検討する

### スプリント3（3週目）：売り始められる

**ゴール**：店の担当者が注文を確認して発送済みにでき、本番環境で売り始められる

| 作業 | US | ポイント |
|------|----|---------|
| 注文の一覧・発送済みにする（発送のお知らせメール） | US-14 | 5 |
| 在庫数の管理（在庫が0の商品は注文できない） | US-13 | 3 |
| 蔵の紹介・お店の情報（特定商取引法の表記を含む） | US-05 | 2 |
| 商品名で検索 | US-01 | 2 |
| テスト（注文の一覧・在庫） | - | 3 |
| 本番環境へのデプロイ | - | 5 |
| **合計** | | **20** |

## 5. 完了の定義

すべてのスプリントで共通。

- 画面で動作を確かめた（スマートフォンでも確認する）
- テストが通っている
- PR を作って main にマージした

## 6. リスク

| リスク | 対策 |
|--------|------|
| 通信販売の免許の取得が間に合わず、サイトができても売れない | スプリント1 の前に、税務署への確認を社長にお願いする |
| 商品の写真や説明文がそろわない | スプリント1 の初日に、商品の情報を店から受け取る日を決める |
| 作業が遅れる | 各スプリントの余裕（合計 7時間）で吸収する。それでも足りないときは、検索（US-01）を次の段階に回す |

## 7. 次の段階（予算の外）

売り始めたあと、社長の目標「1年後に月50本」に向けて、リピートしやすくする機能を追加で提案する。

1. 会員登録・購入履歴（US-09）
2. クーポン（US-10）
3. おすすめ商品の表示（US-12）
4. 売れ筋の確認（US-15）

振り返り（レトロスペクティブ）は、スプリントを実行したあとに行う。
